# 怎样生成一本好的 notebook

一本好的 notebook 不是把资料切成很多页，也不是把模型能想到的内容都塞进页面。它应该像一位老师带学生完成一节课：先建立问题，再铺出路线，每一页只推进一个清楚的学习动作，最后让学生知道自己学会了什么、下一步能做什么。

## 一、先判断这本 notebook 要解决什么

生成前先把需求改写成一个清楚的学习任务：

- 学生是谁：零基础、正在复习、大学课程、研究阅读，还是为某个作业/考试准备。
- 学完要会什么：能解释概念、能做题、能证明、能读代码、能复现方法，还是能做项目决策。
- 范围边界是什么：哪些必须讲，哪些不能扩展，哪些只是背景。
- 输出语言是什么：学生可见文字、讲解口吻、题目说明都要一致。
- 是否有源材料：PDF、PPTX、Markdown、图片、题目、课程标签和课程代码都属于约束，不是可随意发挥的素材。

如果这一步不清楚，后面再漂亮的图片页也只是装饰。好的 notebook 必须先有一个可验证的学习目标。

## 二、建立整本书的课堂主线

页面规划前先写整本书的 `courseSpine`，它至少回答三件事：

- 一句话主线：这本 notebook 到底在带学生理解什么。
- 中心问题：学生一路上反复回到哪个问题。
- 收束方式：最后怎样证明学生不是只看完了页面，而是真的能迁移或检查自己。

主线不是目录。目录只说“讲什么”，主线要说“为什么按这个顺序讲”。例如数学课不应该只是定义、定理、例题、总结，而应该说清楚：学生先遇到什么困惑，哪个定义解决了这个困惑，例题怎样暴露判断方法，最后怎样形成可执行检查。

## 三、规划页面时，每页只做一个教学动作

每页都应该有一个明确的 `pageMove`：

- 这一页从上一页接住什么。
- 这一页让学生先看哪里、判断什么。
- 这一页完成哪个最小学习动作。
- 这一页把学生交给下一页的哪个问题。

不要把一页写成“概念介绍 + 例题 + 易错点 + 总结 + 下节预告”的合集。好的页面通常只有一个主区域、一个例子或图示区域、一个底部收束。页数少时，更应该做 overview 和路线图，而不是把完整课程压成小字讲义。

## 四、例题必须完整，不要只给答案

如果 notebook 的目标包含做题、证明、代码 tracing 或方法训练，例题必须有完整走读：

- 题目或目标要完整出现。
- 已知条件和要证明/要求的东西要分开。
- 解题策略要先出现，再进入步骤。
- 每一步要说明依据，不能只写变形结果。
- 至少写出常见误区或检查方法。
- 最后给出可迁移的判断动作，而不只是最终答案。

例题不足时，notebook 会看起来页数够了，但学习质量是空的。尤其是大学课程，2-4 组完整例题往往比十几页概念摘抄更有价值。

更具体的内容生成要求见 `content-generation-requirements.md`。内容层最重要的是：必须有引入，必须有总结，必须读取原始 PDF 并提取老师已经设计好的阶梯步骤。

## 五、整页图片要像课堂板书，不像宣传页或讲义

当前默认 notebook 是整页图片 PPT。图片页应该是学生正在上课时看到的一块板书或讲台屏幕：

- 16:9 满版画面，不要在大画布里再画一个小纸片或小卡片。
- 学生可见文字要少、准、大，能在缩略图里读出主标题和关键公式。
- 页面上不要出现教案标签，例如“教学目标”“本页主线”“讲解重点”“Teacher move”“QA checklist”。
- 公式、代码、题目原文必须准确，不要为了画面美观改写内容。
- 每页最多 2-3 个主要学习区域；复杂证明或长代码要拆页。
- 风格可以手写、线稿、水彩、卡通或极简，但所有页面要有同一本 notebook 的统一气质。

好的图片页第一眼要让学生知道“先看哪里”，第二眼能看到“这一步为什么重要”。

更完整的图像生成要求见 `image-generation-requirements.md`。其中最重要的是四角标识：每个可讲解学习组件都要用四个纯色角标标出边界，系统才能从整页位图里恢复 focus 区域，再生成遮罩、spotlight 和讲解动作。

## 六、遮罩和讲解动作要服务于学生注意力

图片生成后，要为讲解准备 focus regions。遮罩区域不是随便框几个地方，而是老师讲课时的视线顺序：

- opening：标题、入口问题或本页任务。
- setup：题目、定义、已知条件、代码入口。
- formula / code / visual：本页最关键的表达式、代码块或图示。
- example / proof / strategy：推导、走读或判断方法。
- takeaway：底部收束、检查点或下一页问题。

讲解动作应该先聚焦再说话，不能连续长段旁白却没有视觉指向。每段 speech 只推进一个观察、判断或步骤，避免把整页内容复述成说明书。

## 七、讲解稿要像老师带着看，不像页面注释

好的讲解稿有五个硬要求：

- 先让学生知道看哪里。
- 不复述页面，而解释页面。
- 接住上一页，并交给下一页。
- speech 节奏和 focus 顺序同步，但不是一个 focus 只讲一句。
- 公式讲意思、用途和判断方法，不硬读符号。
- 文本能被语音自然读出来。

更完整的讲解稿要求见 `narration-script-requirements.md`。讲解稿的核心价值是补上页面没有直接写出的依据、选择理由、误区、检查方式和迁移方法。

## 八、公共记忆要写课程私有知识，不堆通用知识

公共记忆的作用是提升后续聊天、答疑和续写质量。它应该优先记录老师实际讲了什么，以及课程里必须遵守的格式：

- 老师强调的主线、术语、判断方式和易错点。
- 证明、代码、答题、计算的课程指定格式。
- 原始材料里出现的标准步骤和老师偏好。
- 只适用于某门课、某个单元或某类题的限制条件。

不要把公共记忆写成通用百科。模型本来就稳定会的通用定义、标准计算技巧和背景知识，不需要大量写入。越是互联网上少、越依赖老师材料、越容易被模型猜错的知识，越应该写进公共记忆。

更完整的公共记忆要求见 `public-memory-requirements.md`。

## 九、生成后必须做质量检查

一轮生成完成后，不要只看有没有页面。至少检查：

- 整本是否有中心问题和清楚收束。
- 每页是否只做一个教学动作。
- 页数是否符合篇幅选择，是否为了压缩而变成密集讲义。
- 例题数量和完整度是否匹配课程目标。
- 图片页是否可读、准确、统一，没有教案标签和小字堆叠。
- 遮罩区域是否覆盖真实学习组件，而不是装饰。
- 讲解稿是否有足够 speech/focus 节奏。
- 公共记忆是否记录了老师讲了什么、课程格式、最终主线、页面索引、例题和易错点。

如果不合格，优先回到页面规划阶段修，而不是只局部改某一页图片。很多质量问题的根源是主线、页数或例题安排错了。

## 十、好 notebook 的最终标准

可以用一句话判断：

学生只看这本 notebook，能不能沿着页面顺序说出“我为什么学这个、每一步在做什么、我现在能独立完成什么”。

如果答案是可以，这本 notebook 才算生成得好。
