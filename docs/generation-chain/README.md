# 好笔记本生成流程

这个目录维护「怎样生成一本好的 notebook」的流程说明。这里不写代码调用链，也不按 API 文件拆说明；这里写的是从用户需求、源材料、页面规划、整页图片、讲解动作到最终质量检查的制作方法。

## 当前文档

- `good-notebook-generation.md`：生成一本高质量 notebook 的完整流程。
- `content-generation-requirements.md`：内容生成的引入、总结和原始 PDF 阶梯步骤要求。
- `image-generation-requirements.md`：整页图片生成的风格、内容、禁用项和硬规范。
- `narration-script-requirements.md`：讲解稿的视线、解释、承接、节奏和语音可读性要求。
- `public-memory-requirements.md`：公共记忆的课程私有知识、格式要求和写入取舍。
- `quality-checklist.md`：生成后判断 notebook 是否合格的检查清单。

## 硬约定

- 四角标识必须按项目的 marker recovery 实现来写：每个可遮罩学习组件使用 4 个同色、实心、纯色小方块。
- 四角标识不是 L 形角线、括号、边框、连线或手绘装饰；4 个小方块之间不能被线条连接。
- marker 颜色只允许来自项目固定颜色池：`#ff0000`、`#00ff00`、`#0048ff`、`#00ffff`、`#ff00ff`、`#ffff00`。
- 普通文字、箭头、边框、图表线条和装饰不能使用 marker 纯色，否则会干扰 recover。
- 生成图片前先写清 component plans；生成后必须跑 recover 检查，并导出每个 focus region 的遮罩预览图。recover 或遮罩预览不通过，不入库。

## 维护规则

1. 先写学习体验，再写技术实现。这里关心学生看完能不能学会，不关心代码文件怎么互相调用。
2. 每次改生成策略，都要回答：它怎样让页面更清楚、例题更完整、讲解更像老师、整本书更连贯。
3. 一条规则如果会影响最终质量，就写成可检查的标准，而不是抽象口号。
4. 生成流程必须覆盖「规划 -> 页面 -> 讲解 -> 公共记忆 -> 质检 -> 迭代」，不能只写 prompt 技巧。
5. 如果某门课、某种材料或某种语言有特殊要求，要写成可复用规则，不要只写单个课程的例子。
