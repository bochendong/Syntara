# 讲解稿要求

讲解稿不是给页面配说明文字，而是把学生的注意力、理解顺序和判断方法带起来。合格的讲解稿至少要满足六件事：知道看哪里、解释为什么、承接前后页、控制节奏、讲公式不枯燥、能被语音自然读出来。

## 一、先让学生知道看哪里

必须包括：

- 每段讲解开始前，有对应的 focus 或 spotlight。
- 讲解要明确当前视觉对象：标题、条件、公式、图示、代码、步骤、答案或总结。
- focus 区域必须框住学习组件，不框装饰、背景、空白或整张大图。
- 不要求一个 focus 只讲一句。一个 focus 可以支撑一小段连续讲解，只要这一小段都围绕同一个学习组件。

为什么要包括：

学生听讲时需要视觉锚点。没有 focus 的讲解会变成悬空旁白，学生不知道正在听哪一块，也无法把语言和页面内容对应起来。

但 focus 不是字幕切换器。它的作用是建立“现在看这一块”的课堂视线，一旦学生已经知道看哪里，讲解可以继续展开观察、原因、误区和过渡。

## 二、不复述页面，而解释页面

必须包括：

- 这一块内容在解决什么问题。
- 这一步为什么可以这样做。
- 当前判断依赖哪些条件、定义、公式、代码状态或图像关系。
- 这里最容易误解什么。
- 学生看完这一页应该带走哪一个可迁移的判断方法。

为什么要包括：

页面文字已经摆在那里，讲解稿的价值不是再念一遍。它要补上页面没有直接写出的因果、依据、选择理由和检查方式，让学生知道“为什么是这一步”，而不是只知道“页面上写了什么”。

## 三、每页都要接住上一页，并交给下一页

必须包括：

- 开头接住上一页留下的问题、结论或困惑。
- 中段回到整本 notebook 的主线。
- 结尾把本页结果交给下一页要解决的问题。
- 每一小段讲解内部也要有承上启下：先接住刚刚看到的内容，再推出接下来要看的内容。

为什么要包括：

notebook 是一节连续的课，不是一组独立图片。没有承接，讲解稿就会变成每页各讲各的，学生很难形成完整路线，也不知道为什么页面要按这个顺序出现。

## 四、节奏要跟学习动作同步

必须包括：

- 每段 speech 只推进一个观察、判断、步骤或提醒。
- 复杂页要拆成多段讲解，不用一大段概括整页。
- 同一个 focus 可以配多段 speech；每次换到新的学习组件前，再切换新的 focus。
- 关键判断处要有停顿、检查或提问式引导。

为什么要包括：

讲解稿是播放出来听的，不是读稿。节奏太快，学生跟不上；节奏太粗，重点会被压平。speech 和 focus 同步，学生才能按老师的视线顺序一步一步看懂。

## 五、公式要讲意思，不要硬读符号

必须包括：

- 先讲公式在解决什么问题，再讲公式里的关键结构。
- 讲使用条件、选择理由、变化方向和检查方法，不把公式逐字符念完。
- 需要读符号时，改成语音能自然表达的说法。
- 公式已经在图片上清楚出现时，讲解稿只解释它的作用和怎么用，不重复朗读整行公式。

为什么要包括：

课堂讲公式，重点不是把符号读出来，而是让学生知道它为什么出现、该怎么用、哪里容易错。硬读公式会让课堂变枯燥，也会让语音模型读错。

## 六、文本必须适合语音朗读

必须包括：

- 讲解稿使用面对面口吻，直接对学生说话。
- 数学、代码、符号和缩写要写成语音能自然读出的表达，不能保留 raw math。
- 学生可听见的语言要和 notebook 的目标语言一致。
- 内部规划词不能进入 speech，例如讲师备注、生成策略、页面设计说明。

为什么要包括：

speech 文本会进入语音模型。排版公式、原始代码符号、讲师备注或中英混杂说明，都会让播放效果不像老师讲课，而像机器在读内部文档。

禁止在 speech 里直接写：

- `2^n`、`x^2` 这类上标写法。
- `log_2`、`a_i` 这类下标写法。
- 原始 LaTeX、花括号、反斜杠、根号、积分号等排版符号。
- 英文公式读法或模型难以稳定朗读的紧凑符号串。

## 七、失败判定

出现以下情况，讲解稿不合格：

- 只是逐字朗读页面文字。
- 只有三两句摘要，没有带学生完成页面里的学习动作。
- 讲解开始时没有当前 focus。
- 把 focus 当成一句话切一次的字幕节奏，导致讲解碎、断、没有承上启下。
- focus 和 speech 对不上。
- 每页之间没有承接关系。
- 只给结论，不解释依据、选择理由、误区或检查方法。
- 硬读公式，或者 speech 里残留 raw math、LaTeX、难读符号、讲师备注或生成提示词。
- 总结页只罗列内容，没有回扣主线和可迁移方法。
